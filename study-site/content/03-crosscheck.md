# 03. ⚠️ 과거 결정 교차점검

## 한 줄 요약
검색된 여러 회의 사이에서 **같은 주제의 결정이 바뀌거나 조건이 추가된 경우**를 감지해, "과거 결정과 함께 다시 확인하라"는 ⚠️ 콜아웃을 띄운다.

## 핵심 개념 (왜)
- **교차점검의 가치:** RAG가 답을 줘도, 과거에 다른 결정이 있었다면 사용자가 놓치기 쉽다 → AI가 **상충/수정**을 먼저 짚어준다.
- **프롬프트 엔지니어링:** 같은 기능도 시스템 프롬프트를 어떻게 쓰느냐로 결과가 갈린다. "완전 모순만 찾아라" vs "수정·추가·예외도 찾아라"는 완전히 다른 동작.
- **환각 방지(중요):** LLM이 **없는 회의를 지어낼 수 있다** → 코드로 "검색된 회의 제목 화이트리스트"를 만들어 그 밖이면 버린다. (프롬프트만 믿지 않는다)

## 우리가 한 것 (어떻게) — `app/ask.py`
```python
CROSSCHECK_SYSTEM = ("...같은 주제(가격·예산·일정...)에 대해 나중 회의에서 결정이 바뀌었거나 "
  "새 조건·예외·할인·한도가 추가/조정돼 '다시 확인할 필요가 있는' 경우를 찾으세요. "
  "완전한 모순뿐 아니라 '기조는 유지하되 일부 조정/추가'도 포함... JSON: {conflict, note, a, b}")

def detect_crosscheck(clova, chunks):
    pairs = {(c["title"], c["meeting_date"]) for c in chunks}
    if len(pairs) < 2: return None                 # 회의가 2개 미만이면 비교 불가
    data = _parse_json(clova.chat(CROSSCHECK_SYSTEM, ...))
    if not data.get("conflict"): return None
    valid = {c["title"] for c in chunks}
    if a["title"] not in valid or b["title"] not in valid: return None   # 환각 방지
    if da > db: a, b = b, a                          # a=이전, b=나중 (날짜 정렬)
    return {"note": ..., "a": a, "b": b}
```

## 막혔던 점 → 해결
- **교차점검이 안 떴다** → 모델이 "중가 유지 + 10% 할인 추가"를 *모순 아님*으로 판단. 원인: 프롬프트가 **완전 모순만** 탐지하게 돼 있었음.
  - 해결: 프롬프트를 **"수정·추가·예외·한도 조정도 포함"** 으로 재작성 → 발화됨.
- **순서 일관성** → 칩이 항상 "과거→현재"로 보이게 **날짜로 a/b 정렬**.
