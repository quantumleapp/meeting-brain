# 10. 발표 자료화 (평가표 기준)

## 한 줄 요약
**평가표(배점)를 기준으로 역산**해, 근거 → 갭 점검 → 디자인 브리프 → 핸드오프 체크리스트 순으로 문서를 만들고, Claude Design 초안을 다시 검토했다.

## 핵심 개념 (왜)
- **평가표 역산:** "무엇을 보여줘야 점수가 나오나"를 먼저 정하고 슬라이드를 구성. **최고 배점에 비중 최대.** (이 프로젝트: AI·클라우드 활용 30점 > 구현 20 > 품질·문제해결 15 > 기획·문서화 10)
- **근거(증거) 기반:** 주장 말고 **실측 수치/실제 화면**(테스트 19, 스모크 7/7, 라이브 데모).
- **갭 분석:** 현재 자료 vs 평가표 → **빠진 것**을 찾아 슬라이드로 채움.
- **민감정보 분리:** 발표/캡처에 키·서버 IP·비번 금지, **합성 데이터만** + "샘플" 표기.

## 우리가 한 것 (어떻게) — 문서 4종
| 문서 | 역할 |
|---|---|
| `PPT_EVIDENCE.md` | 코드/실행에서 확인한 **사실 근거** (각 항목에 근거 파일) |
| `PPT_GAP_CHECK.md` | 평가표 6항목 대비 **현황·갭·리스크** |
| `PPT_DESIGN_BRIEF.md` | Claude Design에 넘길 **의뢰서**(장표 구성·톤·민감정보·요청문) |
| `PPT_HANDOFF.md` | 초안 검토 후 **마감 체크리스트**(더미→실제 캡처 등) |

- **초안 검토:** 장표별 (현재 자료 / 빠진 자료 / 수정 요청 문장) 표로 점검.

## 막혔던 점 → 해결
- **배점 추정 오류** → 스크린샷으로 AI·클라우드를 10점으로 봤으나 **실제 30점(최고)**. 정정 후 강조점을 "구현 데모"→"**AI·Ncloud·화면의 연결**"로 이동.
- **README vs 실배포 불일치** → README는 매니지드 Cloud DB 기준, 실제는 **서버 내 docker pgvector** → 발표에서 정정.
- **데모 슬라이드 더미 숫자**(누적 156 vs 실제 15) → **실제 캡처로 교체** 지시(HANDOFF).
